# 02. 사용자와 문제

> 상태: 가정 기반 사용자 정의 초안. 대상 사용자와 과제 하나 비교 범위는 사용자가 승인했다. 아래 개인의 상황·행동·시간 수치는 설명용 가정이며 실제 인터뷰나 사용자 경험이 아니다.

## 1. 확인한 사실과 가정

| 구분 | 내용 |
|---|---|
| 사용자 진술 | “마감일은 알고 있는데, 지금부터 해도 끝낼 수 있을까?”에 답하는 서비스를 원한다. |
| 합의한 방향 | 대학생이 과제 하나의 필요한 시간과 공부 가능한 시간을 비교하는 첫 버전으로 시작한다. |
| 가정 | 수업·일정 때문에 달력상 남은 기간과 과제에 쓸 수 있는 시간이 다르다. |
| 사용자 피드백 | 날짜별로 매일 가능한 시간을 적는 과정이 불편하다고 말했다. |
| 미확인 | 실제 사용자의 현재 관리 방법, 문제 발생 빈도, 예상 시간의 정확도, 새 평균 입력 방식의 사용성 |

실제 사용자 조사 결과 없음. 가정은 이후 사용자의 설명이나 관찰에 따라 수정한다.

## 2. 대표 사용자 한 명

**대학생 A — 개인 보고서 과제의 완료 가능성을 확인하려는 학생 [가상 사용자]**

- 상황: 보고서 마감 날짜는 알고 있지만 수업과 개인 일정이 있어 남은 기간 전체를 작업에 쓸 수 없다.
- 할 일: 남은 보고서 작업량을 파악하고 마감 전 확보할 수 있는 시간으로 끝낼 수 있을지 판단한다.
- 목적: 시간이 부족하다면 부족분을 알고 일정을 조정한다.
- 서비스 이용 시점: 과제를 시작하기 전 또는 진행 중 계획을 다시 점검할 때.

위 내용은 대표 상황을 설명하기 위한 가정이며, 사용자의 실제 생활을 묘사한 것이 아니다.

## 3. 현재 해결 방법과 불편 [가정]

| 현재 행동 | 겪을 수 있는 불편 | 필요한 도움 |
|---|---|---|
| 과제 공지에서 마감일을 확인한다. | 남은 날짜만으로 실제 작업 시간을 판단하기 어렵다. | 마감 전 실제 확보할 수 있는 시간을 비교에 사용 |
| 남은 작업에 걸릴 시간을 머릿속으로 추정한다. | 필요한 시간과 가능한 시간을 별개로 생각해 부족분을 놓칠 수 있다. | 두 시간을 같은 단위로 비교 |
| 수업과 약속 사이의 빈 시간을 더해 본다. | 사용할 수 없는 시간이나 다른 과제 시간을 포함할 수 있다. | 해당 과제에 배정한 시간만 입력하도록 안내 |
| 시간이 빠듯하면 일정을 바꾸어 다시 생각한다. | 일정 변경으로 부족분이 얼마나 줄었는지 확인하기 번거롭다. | 입력 수정 후 결과 재확인 |

## 4. 핵심 문제 정의

**개인 과제를 수행하는 대학생은 마감일까지 남은 날짜를 알고 있어도, 남은 작업에 필요한 시간과 실제 확보 가능한 시간을 함께 비교하기 어려워 현재 계획으로 시간이 충분한지 판단하기 어렵다. [문제 가설]**

이 서비스는 입력한 시간 사이의 차이를 명확히 보여주는 데 집중한다. 예상 작업 시간 자체를 자동으로 맞히거나 여러 과제에 시간을 자동 배분하는 것은 첫 버전의 목적에 포함하지 않는다.

## 5. 대표 이용 시나리오 [가상 예시]

1. 대학생 A는 금요일 18시에 마감되는 보고서를 수요일에 점검한다.
2. 남은 작업은 자료 정리 2시간, 본문 작성 4시간, 검토 2시간으로 총 8시간이라고 예상한다.
3. 수요일 오전부터 금요일 18시 마감까지 이 과제에 하루 평균 2시간을 쓸 수 있다고 보수적으로 추정한다. 이는 실제 학생의 일정이 아닌 시험용 가정이다.
4. 과제 정보, 필요한 시간 8시간, 하루 평균 가능 시간 2시간을 입력한다. 앱이 3일간 6시간으로 추정한다.
5. 서비스에서 2시간 부족하다는 결과를 확인한다.
6. A가 일정을 검토해 하루 평균 3시간을 실제로 확보할 수 있다고 판단한 경우 평균 입력을 수정한다. 앱의 추정 가능 시간은 9시간이다.
7. 여유 시간이 1시간으로 바뀌는 것을 확인한다. 1시간은 필요한 8시간의 12.5%이므로, 합의한 20% 기준에 따라 노랑으로 표시된다.

이는 계획과 입력값을 조정하는 흐름의 예시다. 실제로 추가 시간을 확보했거나 과제를 완료했다는 관찰 결과가 아니다.

## 6. 사용자에게 필요한 결과와 확인 방법

| 필요한 결과 | 이후 검증할 내용 |
|---|---|
| 현재 계획의 시간 부족 여부를 파악 | 결과 화면에서 상태와 부족 시간을 사용자가 찾아 설명할 수 있는가? |
| 판단 근거를 이해 | 필요한 시간과 가능한 시간의 차이로 나온 결과임을 이해하는가? |
| 일정 변경 효과를 확인 | 가능한 시간을 바꾼 후 여유·부족 시간 변화를 확인할 수 있는가? |
| 결과의 한계를 이해 | 입력한 예상 시간 기준이며 실제 완료 보장은 아니라는 점을 이해하는가? |

현재 판정은 모두 미확인이다. 구현 후 실제 브라우저 조작과 사용자 답변을 `07_check.md`에 기록한다.

## 7. 후속 결정과 검증

- 초기 날짜별 입력은 사용자 피드백으로 부담이 확인되어 하루 평균 한 칸으로 바꿨다. 새 방식의 사용성은 아직 확인하지 못했다. 필요한 시간 대비 20% 여유 기준은 유지한다.
- 실제 경험이 제공되면 가상 시나리오와 다른 점을 기록하고 문제 정의를 보완한다.
- 이 문서의 문제를 근거로 `03_requirements.md`에 REQ-01~REQ-10 후보를 작성했다. 개별 구현·보류 범위는 다음 단계에서 정리한다.
