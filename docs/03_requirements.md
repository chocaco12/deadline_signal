# 03. 요구사항 후보

상태: 요구사항 후보를 REQ-01~10으로 관리한다. 2026-11-18 사용자의 날짜별 입력 불편 피드백에 따라 REQ-02·REQ-07의 입력·계산 방식을 하루 평균 시간으로 변경했다. 20% 신호등 규칙은 유지한다. 실제 시험 결과는 `07_check.md`에 기록한다.

## 1. 합의한 판단 규칙

- 대상: 개인 과제 하나의 시간을 비교하려는 대학생.
- 필요한 시간 N: 이미 쓴 시간이 아닌 앞으로 남은 작업의 예상 시간. 0보다 커야 한다.
- 가능한 시간 A: 하루 평균 가능 시간을 오늘부터 마감일까지 각 날짜에 적용하고, 오늘·마감일의 실제 남은 물리적 시간을 넘지 않게 제한한 합계. 일정별 실제 확보 시간은 사용자가 추정한다.
- 오늘은 지금 이후, 마감일은 마감 시각 이전의 시간만 포함한다. 같은 날 마감이면 두 조건을 모두 적용한다.
- 빨강: A < N. 부족 시간은 N − A.
- 노랑: N ≤ A < 1.2 × N. 여유는 있지만 20% 미만이며, A = N이면 여유 0시간이다.
- 초록: A ≥ 1.2 × N. 필요한 시간 대비 20% 이상의 여유가 있다.
- 20%는 첫 버전의 합의한 규칙이며, 실제 완료 가능성을 보장하는 검증된 예측 기준이 아니다.
- 색상뿐 아니라 상태 이름, 필요한 시간, 가능한 시간, 여유·부족 시간을 함께 표시한다.

## 3. 설계 단계에서 구체화할 사항

- 시간 입력 단위와 소수점 허용 범위, 표시 시 반올림 방식. 상태 판정은 표시를 위해 반올림한 값에 영향받지 않도록 한다.
- 부분 날짜 상한은 실제 일정을 알 수 없으므로 수업·수면·다른 과제 시간까지 자동 제외하지 않는다. 사용자가 보수적인 평균을 입력해야 한다.
- 평균 방식은 날마다 크게 다른 일정을 표현하지 못한다. 결과에 추정치임을 명시하고 실제 사용자 평가에서 확인한다.
- 화면을 오래 열어 두었을 때 지난 마감과 오늘의 잔여 시간 재검증.
- 기기 현지 시각을 사용할지 등 날짜·시각 처리 규칙은 설계에 명시한다.
