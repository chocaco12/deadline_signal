# 03. 요구사항 후보

상태: 요구사항 후보 작성. 날짜별 시간 입력, 필요한 시간 대비 20% 여유 기준, 근거를 포함한 결과와 수정·재계산 흐름은 사용자가 승인했다. 아래 우선순위는 제안이며 최종 구현·보류 목록은 `04_requirements_mvp.md`에서 정리한다. 기능 구현 및 브라우저 검증은 아직 하지 않았다.

## 1. 합의한 판단 규칙

- 대상: 개인 과제 하나의 시간을 비교하려는 대학생.
- 필요한 시간 N: 이미 쓴 시간이 아닌 앞으로 남은 작업의 예상 시간. 0보다 커야 한다.
- 가능한 시간 A: 오늘부터 마감일까지 해당 과제에 사용할 날짜별 시간의 합계.
- 오늘은 지금 이후, 마감일은 마감 시각 이전의 시간만 포함한다. 같은 날 마감이면 두 조건을 모두 적용한다.
- 빨강: A < N. 부족 시간은 N − A.
- 노랑: N ≤ A < 1.2 × N. 여유는 있지만 20% 미만이며, A = N이면 여유 0시간이다.
- 초록: A ≥ 1.2 × N. 필요한 시간 대비 20% 이상의 여유가 있다.
- 20%는 첫 버전의 합의한 규칙이며, 실제 완료 가능성을 보장하는 검증된 예측 기준이 아니다.
- 색상뿐 아니라 상태 이름, 필요한 시간, 가능한 시간, 여유·부족 시간을 함께 표시한다.

## 2. 요구사항 후보

| 요구사항 번호 | 연결된 사용자 문제 | 필요한 기능 | 사용자 행동 | 기대 결과 | 완료 기준 | 우선순위와 근거 |
|---|---|---|---|---|---|---|
| REQ-01 | 비교할 과제와 마감이 명확해야 함 | 과제명·마감 날짜와 시각·남은 예상 작업 시간 입력 | 과제 정보 입력 | 비교의 기준 설정 | 유효한 과제명, 미래 마감, 양수 작업 시간을 입력해 비교를 진행할 수 있음 | 높음 — 모든 계산의 출발점 |
| REQ-02 | 날짜마다 실제 사용 가능한 시간이 다름 | 오늘~마감일 날짜 목록과 날짜별 시간 입력 | 해당 과제에 쓸 시간 입력, 불가능한 날은 0 입력 | 날짜별 계획을 돌아보고 가능 시간을 합산 | 1·2·2시간 입력 시 합계 5시간. 마감 이후 날짜는 목록에서 제외. 오늘·마감일의 제한 안내 표시 | 높음 — 합의한 입력 방식 |
| REQ-03 | 시간 부족 여부를 바로 판단하기 어려움 | 시간 비교와 신호등 분류 | 계산 버튼 누르기 | 부족·빠듯·여유 상태 확인 | N=10에서 A=9.5는 빨강, 10과 11.5는 노랑, 12와 12.5는 초록 | 높음 — 핵심 판단 기능 |
| REQ-04 | 색상만으로는 이유나 부족분을 알기 어려움 | 상태 이름·비교 수치·안내 문구 표시 | 결과 읽기 | 부족분과 판단 근거 이해 | N=8, A=5이면 빨강·부족 3시간·필요 8시간·가능 5시간 및 추정값 기준 안내를 함께 표시. A=N이면 부족이라고 하지 않고 여유 0시간 표시 | 높음 — 결과 해석과 접근성 |
| REQ-05 | 일정을 바꿨을 때 효과를 다시 확인해야 함 | 입력 수정과 재계산 | 날짜별 시간이나 작업 시간 수정 후 계산 | 최신 계획의 결과 확인 | N=8, A=5에서 A=9로 수정·재계산하면 노랑·여유 1시간으로 변경. 입력 변경 후에는 기존 결과가 최신인 것처럼 보이지 않음 | 높음 — 계획 조정까지 흐름 완결 |
| REQ-06 | 잘못된 입력이 잘못된 판단으로 이어짐 | 필수값·숫자·시간 범위 검증 | 누락·음수·지난 마감 등을 입력 | 오류 원인과 수정 방법 확인 | 빈 과제명, 누락·잘못된 마감, N≤0, 음수·숫자가 아닌 가능 시간을 거부. 오류 위치 안내 후 계산 차단. 모든 날짜 0시간은 유효하며 N시간 부족 표시 | 높음 — 판단의 기본 신뢰성 |
| REQ-07 | 날짜별로 물리적으로 불가능한 시간을 넣을 수 있음 | 날짜별 잔여 시간 상한 검사 | 해당 날짜에 남은 실제 시간보다 큰 값 입력 | 과대 입력을 수정하도록 안내 | 계산 시점부터 마감 시각 사이에서 각 날짜가 차지하는 길이를 초과한 입력은 거부. 같은 날 마감은 지금~마감 구간을 적용 | 높음 제안 — 마감 전 시간만 비교하기 위함 |
| REQ-08 | 접속·화면 조작의 부담 | 로그인 없는 기본 이용과 읽기 쉬운 입력 화면 | 모바일 또는 데스크톱 브라우저에서 접속 | 핵심 흐름 수행 | 로그인 없이 입력→결과→수정 가능. 키보드로 입력·계산 가능하며 입력에 이름표가 있음. 좁은 화면에서도 주요 입력과 결과를 읽을 수 있음 | 높음 — 과제 제약과 기본 사용성 |
| REQ-09 | 다시 접속할 때 입력 반복 | 브라우저 내 입력값 저장·복원 | 재접속 | 이전 입력 재사용 | 저장을 채택할 경우 새로고침 후 입력 복원, 지우기 가능, 지난 날짜·마감 재검증 | 낮음 — 첫 계산 흐름에는 필수 아님 |
| REQ-10 | 여러 과제의 시간 경쟁 | 여러 과제 비교·자동 시간 배분 | 과제 여러 개 등록 | 중복 시간과 우선순위 확인 | 채택 시 총 가능 시간을 중복 배정하지 않는 규칙과 시험 기준을 별도 정의해야 함 | 첫 버전 제외 — 사용자와 합의한 단일 과제 범위를 벗어남 |

## 3. 설계 단계에서 구체화할 사항

- 시간 입력 단위와 소수점 허용 범위, 표시 시 반올림 방식. 상태 판정은 표시를 위해 반올림한 값에 영향받지 않도록 한다.
- 날짜별 시간 상한 검사는 실제 일정을 알 수 없으므로 수업·수면·다른 과제 시간까지 자동 제외하지 않는다. 사용자가 실제 배정 시간을 입력한다.
- 마감 변경으로 날짜 목록이 바뀔 때 기존 값의 유지·제외 방법과 안내.
- 화면을 오래 열어 두었을 때 지난 마감과 오늘의 잔여 시간 재검증.
- 기기 현지 시각을 사용할지 등 날짜·시각 처리 규칙은 설계에 명시한다.
