# 06. 화면과 동작 설계 — 과제 신호등

> 상태: REQ-01~08을 구현하고 로컬 브라우저에서 주요 흐름을 확인했다. 날짜별 입력과 20% 신호등 기준은 사용자와 합의했다. 입력 단위, 오류 문구, 마감 변경 처리와 1년 이내 제한은 구현 세부 선택이다.

## 1. 화면 구성과 이용 흐름

첫 버전은 로그인 없이 한 화면에서 과제 **하나**를 비교한다.

### 사용자 제공 디자인 반영 (2026-11-15)

사용자가 제공한 모바일 대시보드 HTML 시안의 짙은 남색 상단 바, 밝은 배경, 흰색 카드, 세로 신호등, 수치 카드를 화면에 반영했다. 화면 폭은 최대 480px로 제한하고 모바일에서는 화면 폭에 맞게 표시한다. 시안의 고정 예시 과제·시간과 신호를 수동으로 바꾸는 버튼은 실제 계산 결과와 충돌하므로 사용하지 않는다. 저장·공유·설정·다중 화면 메뉴도 이번 MVP 범위 밖이다. 초기에는 신호등을 흐리게 보여 주고, 유효한 입력으로 계산한 뒤에만 해당 불이 켜진 결과를 표시한다. 외부 폰트·Tailwind CDN 없이 로컬 CSS로 스타일을 구현해 정적 파일만으로 실행한다.

```text
과제 신호등
“지금부터 해도 끝낼 수 있을까?”

① 과제 정보
  과제명 | 마감 날짜·시각 | 앞으로 필요한 작업 시간

② 날짜별 공부 가능 시간
  오늘부터 마감일까지 날짜별 입력칸
  “이 과제에 실제로 쓸 시간만 입력하세요.”

  [시간 비교하기]

③ 결과
  빨강·노랑·초록 상태 이름과 설명
  필요한 시간 | 가능한 시간 | 부족 또는 여유 시간
  “입력한 예상 시간 기준이며 완료를 보장하지 않습니다.”
```

사용자는 과제 정보 입력 → 날짜별 가능 시간 입력 → **시간 비교하기** 버튼 → 결과 확인 → 필요하면 입력 수정 → 다시 계산 순서로 이용한다. 날짜별 입력을 바꾸면 기존 결과는 즉시 숨기고 “입력이 바뀌었어요. 다시 비교해 주세요.”라고 안내한다. 결과 영역은 계산 성공 전까지 보이지 않는다.

## 2. 입력·계산 규칙

| 항목 | 설계 규칙 |
|---|---|
| 과제명 | 앞뒤 공백을 제외하고 1자 이상. 결과 제목에 표시하되 HTML 코드로 해석하지 않는다. |
| 마감 날짜·시각 | 사용자의 브라우저에 설정된 현지 날짜·시각을 기준으로 받는다. 계산 버튼을 누를 때 현재 시각보다 미래이고, 오늘부터 366번째 날짜보다 앞이어야 한다. 시간대 자동 변환이나 학교 시스템 연동은 하지 않는다. |
| 앞으로 필요한 작업 시간 N | 이미 쓴 시간은 제외한다. `0.5`시간(30분) 단위의 양수로 입력한다. |
| 날짜별 가능 시간 | 오늘부터 마감일까지만 표시한다. 각 날짜의 입력 기본값은 `0`시간이며, 해당 과제에 실제로 배정할 시간을 `0.5`시간 단위로 입력한다. 다른 과제·수업·수면 시간은 사용자가 제외한다. |
| 가능한 시간 A | 날짜별로 유효하게 입력한 시간을 모두 더한 값. 모든 날짜가 `0`이면 `A=0`으로 유효하다. |
| 오늘·마감일의 상한 | 계산 시각부터 해당 날짜가 끝날 때까지, 또는 해당 날짜 시작부터 마감 시각까지 중 실제로 남은 구간만 허용한다. 같은 날 마감이면 **지금부터 마감까지**가 상한이다. 미래의 중간 날짜는 그 날짜의 길이를 상한으로 한다. 화면의 최대 입력 가능 시간은 이 길이를 0.5시간 단위로 **내림**한 값이다. |
| 시간 표시 | 30분 단위이므로 정수 시간은 `8시간`, 반 시간은 `8.5시간`처럼 표시한다. 내부 판정은 표시 문자열이나 반올림 결과가 아닌 입력된 30분 단위 값으로 한다. |

날짜별 물리적 상한은 입력한 시간이 그 날짜의 남은 시간보다 클 수 없게 하는 최소 검증이다. 수업·식사·다른 과제 시간을 앱이 알 수 없으므로, 실제 가능한 시간은 사용자가 판단한다. 날짜별 안내에 “오늘은 지금 이후, 마감일은 마감 시각 전까지만 적으세요”를 표시한다.

### 신호등 판정

| 조건 | 상태 | 결과 문구 예 |
|---|---|---|
| `A < N` | 🔴 시간 부족 | `3시간 부족해요` |
| `N ≤ A < 1.2 × N` | 🟡 빠듯함 | `1시간 여유가 있지만 빠듯해요` |
| `A ≥ 1.2 × N` | 🟢 여유 있음 | `2시간 여유가 있어요` |

정확히 필요한 시간과 같으면 노랑·`여유 0시간`이다. 정확히 20% 여유가 생기면 초록이다. 입력 시간을 30분 단위의 정수 개수로 바꿔 합산하고, 초록 판정은 `5 × 가능한 30분 개수 ≥ 6 × 필요한 30분 개수`로 비교한다. 표시용 반올림 때문에 경계 판정이 달라지지 않는다. 20%는 계획을 돕기 위한 첫 버전의 규칙이며 완료 가능성에 대한 통계적 예측이 아니다.

## 3. 요구사항별 화면·동작 설계

| 요구사항 | 화면 구성과 사용자 흐름 | 입력 → 출력 및 버튼 동작 | 잘못된 입력 처리 |
|---|---|---|---|
| REQ-01 | 상단 과제 정보 영역에서 과제명, 마감 날짜·시각, 남은 작업 시간을 입력한다. | 유효한 미래 마감이 정해지면 날짜별 입력 목록을 만든다. **시간 비교하기**를 누를 때 세 값을 다시 읽는다. | 과제명 공백, 마감 누락·지난 시각, N이 비어 있거나 0 이하이면 항목별 안내를 보이고 계산하지 않는다. |
| REQ-02 | 마감이 정해지면 오늘~마감일의 각 날짜와 시간 입력칸을 표시한다. | 각 입력의 합계 A를 계산한다. 예: `1+2+2=5시간`. 불가능한 날짜는 `0`으로 둔다. | 빈칸, 음수, 숫자가 아닌 값, 0.5시간 단위가 아닌 값은 해당 날짜에 오류를 표시한다. 모두 0이면 계산한다. |
| REQ-03 | 계산 성공 시 결과 영역에 신호 색과 상태 이름을 보여준다. | **시간 비교하기**를 누르면 A와 N을 비교해 빨강·노랑·초록을 판정한다. | 입력 검증이 실패하면 신호등을 보여주지 않는다. |
| REQ-04 | 결과 영역에 과제명, 상태 이름, N, A, `부족 N−A` 또는 `여유 A−N`, 추정값 안내를 표시한다. | `N=8, A=5` → 빨강·3시간 부족. `N=A` → 노랑·여유 0시간. | 계산 불가 상태에서는 오래된 수치를 남겨 두지 않고 오류 안내만 보여준다. |
| REQ-05 | 사용자가 기존 입력칸을 수정하고 같은 버튼으로 다시 계산한다. | 입력이 바뀌면 결과를 숨긴다. `N=8, A=5`에서 A를 9로 수정·재계산하면 노랑·여유 1시간을 표시한다. | 수정한 값이 유효하지 않으면 이전 결과를 다시 표시하지 않는다. |
| REQ-06 | 각 입력 가까이에 짧은 오류 문구를 두고, 맨 위에 오류 요약을 표시한다. | **시간 비교하기**를 누르면 모든 필수값과 시간 범위를 검사한다. | 첫 번째 잘못된 입력에 키보드 초점을 옮긴다. 수정하면 해당 오류를 지우며, 모든 오류가 없어야 결과를 보여준다. |
| REQ-07 | 오늘·마감일의 각 날짜 입력 옆에 남은 시간의 최대값을 안내한다. | 계산을 누르는 현재 시각 기준으로 날짜별 상한을 다시 계산한다. 예: 마감까지 2시간 남았는데 같은 날에 3시간을 넣으면 거부한다. | 상한 초과 날짜와 입력 가능한 최대 시간을 알려준다. 같은 날 마감, 자정 통과, 오래 열어 둔 화면도 계산 시 재검사한다. |
| REQ-08 | 한 열 중심의 화면으로 모바일에서도 입력·결과를 읽게 한다. 모든 입력에 보이는 이름표가 있다. | 로그인 없이 키보드로 입력하고 Enter 또는 버튼으로 계산한다. 결과 갱신은 보조기술에 전달한다. | 오류는 색상만으로 전달하지 않고 글로도 표시하며, 오류 입력과 설명을 연결한다. |

## 4. 날짜 목록 변경과 오래 열린 화면

1. 마감 날짜·시각이 **유효한 미래 값으로 확정되면** 목록을 다시 만든다. 날짜를 키로 삼아 **겹치는 날짜**의 기존 시간을 유지한다. 새 날짜는 `0`으로 시작하고, 새 범위 밖의 날짜는 삭제한다. 기존 값을 유지한 날짜도 새 상한을 넘는지 다시 검사한다.
2. 마감 입력을 편집하는 동안 값이 잠시 비거나 유효하지 않으면 날짜 목록과 결과를 숨기되, 기존 날짜별 값은 화면 내부에 임시로 유지한다. 유효한 마감을 다시 입력했을 때 겹치는 날짜의 값을 복구한다. 과제명이나 N을 바꾸더라도 결과는 숨긴다.
3. 화면을 자정 너머로 오래 열었거나 마감 시각이 지나면, **시간 비교하기**를 누를 때 현지 현재 시각으로 날짜 목록과 상한을 다시 계산한다. 지난 날짜의 값은 계산에 포함하지 않는다. 날짜 구성이 바뀌었다면 사용자에게 목록이 갱신됐다고 알리고 **그 클릭에서는 결과를 계산하지 않는다**. 새 목록을 확인한 뒤 다시 버튼을 누른다.
4. 현재 날짜의 실제 남은 시간이 기존 입력값보다 적어진 경우, 해당 값을 자동으로 줄이지 않는다. 상한 안내를 최신 값으로 바꾸고 REQ-07 오류를 보여주어 사용자가 수정하도록 한다.

입력은 현재 화면에서만 유지한다. 새로고침 후 복원하는 기능은 REQ-09로 보류했다.

## 5. 화면 문구와 접근성

- 버튼은 `시간 비교하기` 하나를 주 동작으로 사용한다. 결과 이후 같은 버튼을 다시 눌러 재계산한다.
- 상태는 `🔴 시간 부족`, `🟡 빠듯함`, `🟢 여유 있음`처럼 글자로 함께 보여준다. 배경색만으로 구분하지 않는다.
- 오류 예: `마감은 현재보다 늦은 날짜와 시간으로 입력해 주세요.`, `필요한 시간은 0.5시간 단위의 양수로 입력해 주세요.`, `오늘은 최대 2시간까지만 입력할 수 있어요.`
- 결과 아래에 `입력한 예상 작업 시간과 공부 가능 시간을 기준으로 계산했어요. 실제 완료를 보장하지 않습니다.`를 표시한다.
- 입력과 오류 문구는 화면에서 연결하고, 계산 결과는 화면 읽기 기능이 알아차릴 수 있도록 갱신 안내 영역을 둔다.
- 모바일 화면에서는 가로 스크롤 없이 주요 입력과 결과를 읽을 수 있도록 한 열로 배치한다.

## 6. 파일과 구현 원칙

- `index.html`: 화면의 제목, 입력 영역, 계산 버튼, 오류 요약과 결과 영역.
- `css/style.css`: 좁은 화면 대응, 입력·오류·신호등의 색과 배치.
- `js/app.js`: 날짜 목록 생성, 값 검증, 시간 합산, 상태 판정, 결과 갱신.
- 서버·계정·외부 API·비밀 키가 필요하지 않은 정적 웹앱으로 구현한다. 입력값을 외부로 전송하지 않는다.
- 과제명은 화면에 글자로만 넣어 사용자가 입력한 HTML이 실행되지 않게 한다.

## 8. 남아 있는 확인

- 0.5시간 단위와 날짜별 기본값 0은 입력 부담을 줄이기 위한 설계 선택이다. 실제 사용자가 이해하기 쉬운지는 구현 후 확인한다.
- 마감까지 30분 미만인 날짜의 허용 최대값은 0시간이다. 이 경우 30분 단위 입력으로는 양수 시간을 표현할 수 없으며, 화면에서 그 이유를 안내한다.
- 날짜별 입력칸이 과도하게 늘지 않도록 마감은 오늘부터 1년 이내로 제한했다. 이는 구현 중 추가한 REQ-01·REQ-02의 입력 범위 제한이다. 1년보다 먼 과제는 이번 버전에서 비교할 수 없다. 실제 날짜별 목록의 사용성은 추가 확인이 필요하다.
- 사용자의 기기 시각이 틀리면 오늘과 마감의 계산도 달라질 수 있다. 결과에는 기기 현지 시각 기준임을 표시한다.
- REQ-09 입력 저장과 REQ-10 여러 과제 비교는 이 설계에 포함하지 않는다.
- 구현 중 규칙을 바꾸면 변경 이유와 관련 REQ 영향을 이 문서와 범위·시험 문서에 반영한다.
