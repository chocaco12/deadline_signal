# 06. 화면과 동작 설계 — 과제 신호등

> 현재 설계: 하루 평균 공부 가능 시간을 한 번 입력하는 단일 과제 비교 화면. 2026-11-18 사용자 피드백 “일자마다 적는 게 불편하다”를 반영해 기존 날짜별 입력 설계를 대체했다. 20% 신호등 판정과 REQ-01~08 번호는 유지한다.

## 1. 화면과 이용 흐름

로그인 없이 한 화면에서 과제 하나를 비교한다. 모바일 대시보드 시안의 남색 상단 바, 밝은 배경, 흰 카드, 세로 신호등과 시간 수치 카드를 유지한다. 초기 신호등은 흐리게 표시하고, 유효한 입력으로 계산한 뒤에만 결과 카드의 해당 불을 켠다.

```text
과제 기본 설정: 과제명 · 마감 날짜와 시각 · 앞으로 필요한 시간 N
하루 평균 공부 가능 시간: 평균 H 한 칸 · 보수적 입력 안내
[시간 비교하기]
결과: 신호 · 필요한 시간 N · 추정 가능한 시간 A · 차이 · 계산 근거와 한계
```

과제 정보와 H 입력 → 계산 → 결과 확인 → 값 수정 → 이전 결과 숨김 → 다시 계산 순서다. 저장·공유·여러 과제 메뉴는 REQ-09~10 등 보류 범위이므로 표시하지 않는다. 외부 폰트·CDN·서버 없이 로컬 정적 파일로 실행한다.

## 2. 입력과 추정 규칙

| 항목 | 규칙 |
|---|---|
| 과제명 | 앞뒤 공백을 제외하고 1자 이상. 결과에 글자로만 표시하고 HTML로 해석하지 않는다. |
| 마감 날짜·시각 | 브라우저 현지 시각을 기준으로 현재보다 미래, 오늘부터 1년 이내. 시간대 자동 변환이나 학교 시스템 연동 없음. |
| 필요한 시간 N | 이미 쓴 시간은 제외한다. 0.5시간(30분) 단위의 양수. |
| 하루 평균 가능 시간 H | 이 과제에 쓸 수 있는 평균을 0~24시간, 0.5시간 단위로 입력한다. 0도 유효하다. 수업·휴식·다른 과제 시간을 제외하고 일정이 크게 다르면 보수적으로 입력하도록 안내한다. |
| 가능한 시간 A | 오늘부터 마감일까지 현지 날짜별로 `min(H, 그 날짜의 계산 시점~마감 사이 실제 남은 시간)`을 합산한다. 실제 남은 시간은 30분 단위로 내림한다. 같은 날 마감이면 하루만 계산한다. |
| 표시 | 필요한 시간, 추정 가능한 시간, 차이와 함께 `하루 평균 H × 오늘부터 마감일까지 D일`을 보인다. H를 모두 반영하지 못한 날짜가 있으면 그 날짜 수와 상한 적용 사실을 안내한다. |

예: 2026-11-18 오전 10시부터 11-21 오후 11시 30분까지 H=2시간이면 4일에 2시간씩 적용해 A=8시간이다. 같은 날 오전 10시부터 오전 11시 30분 마감이면 H=2시간이어도 실제 남은 시간이 1시간 30분보다 조금 적으므로 30분 단위 내림 후 A=1시간이다. 앱이 수업·약속을 알지 못하므로 A는 **예상치**이며 실제 확보 시간이나 과제 완료를 보장하지 않는다.

### 신호등 판정

| 조건 | 상태 | 예시 |
|---|---|---|
| `A < N` | 🔴 시간 부족 | N=10, A=8 → 2시간 부족 |
| `N ≤ A < 1.2 × N` | 🟡 빠듯함 | N=8, A=8 → 여유 0시간 |
| `A ≥ 1.2 × N` | 🟢 여유 있음 | N=6.5, A=8 → 1.5시간 여유 |

모든 계산은 30분 단위의 정수 개수로 수행한다. 초록 경계는 `5 × A단위 ≥ 6 × N단위`로 판정해 표시용 반올림 때문에 결과가 바뀌지 않게 한다. 20%는 계획을 돕기 위한 합의 규칙이며 통계적 예측이 아니다.

## 3. 요구사항별 화면·동작·오류

| 요구사항 | 화면과 사용자 행동 | 계산 또는 출력 | 잘못된 입력 처리 |
|---|---|---|---|
| REQ-01 | 과제명, 마감, N을 입력하고 계산 버튼 클릭 | 비교 대상과 기간을 설정 | 공백 과제명, 지난·누락된 마감, N≤0, 30분 단위 위반은 항목별 오류 |
| REQ-02 | 하루 평균 H를 한 칸에 입력 | 날짜별 반복 입력 없이 A 추정, 기간·H 근거 표시 | H가 비거나 유효하지 않으면 계산 차단 |
| REQ-03 | `시간 비교하기` 클릭 | A와 N으로 빨강·노랑·초록 판정 | 입력 오류가 있으면 신호 결과를 보이지 않음 |
| REQ-04 | 결과 카드 읽기 | 상태 이름·N·A·차이·추정 안내 표시 | 계산 불가 시 오래된 수치 숨김 |
| REQ-05 | N, H, 마감 등을 수정하고 다시 클릭 | 수정 즉시 결과를 숨기고 최신 입력으로 재계산 | 수정 후 오류가 있으면 이전 결과 복원 안 함 |
| REQ-06 | 입력 오류를 확인하고 수정 | 입력 근처 문구, 오류 요약, 첫 오류 항목으로 초점 이동 | H<0, H>24, 30분 단위 위반, 빈칸 및 기타 오류를 구분 |
| REQ-07 | 마감과 H를 입력하고 결과 근거 읽기 | 오늘·마감일의 물리적 남은 시간을 자동 상한으로 적용. 같은 날 한 번 계산 | 지난 마감은 거부. 화면을 오래 열었으면 클릭 시 현재 시각으로 재계산 |
| REQ-08 | 모바일·데스크톱에서 키보드 또는 터치로 사용 | 보이는 이름표, 텍스트 상태 이름, 화면 읽기용 결과 갱신 영역 | 오류는 색만으로 표현하지 않고 설명과 입력을 연결 |

입력이 바뀌면 이전 결과를 숨기고 `입력이 바뀌었어요. 다시 비교해 주세요.`를 표시한다. 마감은 계산 버튼을 누르는 시각에 다시 검증한다. 오늘에서 다음 날로 자정이 바뀌었더라도 그 시점의 날짜부터 재계산하므로 지난 날짜는 자동으로 제외된다. H 자체를 사용자가 실제로 확보할 수 있는지는 앱이 검증하지 못한다.

## 4. 변경 영향과 보류

날짜별 1·2·2시간처럼 다른 값을 넣던 방식은 더 이상 없다. 그 대신 한 번의 평균 입력으로 빠르게 결과를 얻는다. 날마다 공부 시간이 크게 달라지면 한 숫자가 실제 일정을 표현하지 못해 결과가 낙관적일 수 있다. 사용자는 보수적으로 H를 정하고 결과를 추정으로 해석해야 한다. 날짜별 상세 조정 기능을 다시 넣으려면 사용자 피드백과 새 범위 결정이 필요하다.

REQ-09 저장·복원, REQ-10 여러 과제 비교는 여전히 보류·제외다. 새로고침하면 입력은 유지되지 않는다.
